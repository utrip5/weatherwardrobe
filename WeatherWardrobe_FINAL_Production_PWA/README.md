# WeatherWardrobe — FINAL PWA

## Что это
Готовая web-first версия WeatherWardrobe. Её можно разместить на обычном HTTPS static hosting. После публикации она не зависит от домашнего компьютера.

Поддерживает:
- русский / English;
- GPS и поиск города;
- текущую погоду;
- feels-like;
- ветер, направление и порывы;
- влажность, облачность;
- дождь, снег, вероятность осадков;
- UV;
- отдельную вкладку прогноза на 7 дней;
- подбор одежды для каждого дня;
- почасовую подборку для ближайших часов;
- мужской / женский / унисекс профиль;
- чувствительность к холоду;
- тип активности;
- расширенный каталог одежды;
- расширенный каталог обуви;
- собственный гардероб и фото вещей;
- PWA install;
- service worker;
- базовые security headers.

## Главное изменение алгоритма
При температуре 27°C+ приложение НЕ рекомендует худи, свитер, куртку или дождевик без реальной причины.

Тёплый слой добавляется только при низкой ощущаемой температуре. Верхняя одежда появляется при:
- низкой температуре;
- сильном ветре/порывах;
- существенном риске осадков;
- снеге.

Дождевик — только при заметном риске/наличии осадков, а не просто потому, что прогноз содержит облачность.

## Запуск локально
```bash
python -m http.server 8080
```
Откройте http://localhost:8080

## Публикация
Загрузите содержимое папки на HTTPS static hosting:
- Cloudflare Pages
- Netlify
- Vercel
- GitHub Pages
- собственный HTTPS Apache/Nginx

Для production предпочтителен HTTPS. Файлы `_headers` и `.htaccess` содержат рекомендуемые security headers для соответствующих серверов.

## Важно про погоду
Приложение использует Open-Meteo напрямую из браузера:
- https://api.open-meteo.com/
- https://geocoding-api.open-meteo.com/

API key в клиенте не хранится. Перед коммерческим запуском проверьте актуальные условия использования и attribution Open-Meteo.

## Безопасность
В проекте:
- нет секретных API-ключей;
- включён CSP;
- ограничены connect-src/img-src/script-src;
- нет inline JavaScript;
- пользовательский текст экранируется перед вставкой в DOM;
- фото ограничено 5 MB и MIME types;
- localStorage данные валидируются при загрузке;
- ограничено число сохранённых вещей;
- добавлены security headers;
- geolocation разрешена только для текущего origin через Permissions-Policy.

Это хороший baseline для static PWA, но не заменяет security audit перед коммерческим запуском.

## iPhone
Откройте production HTTPS URL в Safari → Share → Add to Home Screen.

Это PWA, а не нативный WidgetKit widget. Настоящий iOS Home Screen/Lock Screen widget требует отдельного native WidgetKit target.

## Android
Откройте HTTPS URL в Chrome → Install app / Add to Home screen.

## Следующий коммерческий этап
Для синхронизации гардероба между устройствами потребуется backend/auth/database. Для первой версии это специально не добавлено: приложение работает без аккаунта и без хранения личных данных на сервере.
